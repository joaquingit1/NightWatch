## 1. 目标

下一阶段需要把当前“根据地图完成度自动探索或巡逻”的隐式行为，升级成操作员能够理解、切换和随时接管的明确产品流程：

1. 机器狗具有“探索”和“巡航”两种任务模式。
2. 每种任务模式都可以处于“自主”或“手动”控制状态。
3. 探索模式只负责探索未知空间和建图，不运行疲劳检测，不与人互动。
4. 巡航模式运行疲劳检测、周期性仰头观察、人员干预、问卷等待和 Bedroom 护送。
5. 工作台提供按钮、键盘控制、状态解释、带疲劳标注的视频和三维地图入口。
6. 操作员在任何行为阶段都可以立即接管或停止机器狗。

## 2. 核心状态模型

不要把所有行为塞进一个布尔值。运行状态分成四个相互独立但受约束的维度。

### 2.1 任务模式 `mission_mode`

| 值 | 说明 |
| --- | --- |
| `exploration` | 仅探索、建图和避障；疲劳检测及人员互动全部关闭 |
| `cruise` | 巡航、疲劳检测、观察、人员交互和 Bedroom 护送全部可用 |

启动时默认进入 `exploration`。这能保证服务重启或地图状态不明确时，不会立即对人执行自动行为。

### 2.2 控制模式 `control_mode`

| 值 | 说明 |
| --- | --- |
| `autonomous` | 行为监督器拥有运动控制权，执行探索或巡航 |
| `manual` | 操作员拥有运动控制权，自主导航立即停止 |

手动控制始终高于探索、巡航、观察、人员干预和护送。切换到手动后，当前导航目标必须取消，速度归零，然后才接受工作台方向指令。

### 2.3 疲劳自动接管 `fatigue_auto_takeover`

- 仅在 `mission_mode=cruise` 时有效。
- 自主控制时默认为开启。
- 每次进入手动控制时默认为关闭，工作台可单独打开。
- 关闭时疲劳算法仍运行、视频仍显示分数、工作台仍告警，但不会自动抢占手动运动。
- 打开后，满足连续阈值的疲劳对象可以进入接近和交互流程。
- 即使打开，操作员新的方向键、停止或“切换手动”仍可立即中断自动行为。

### 2.4 人员交互状态 `interaction_state`

```text
idle
  → scheduled_scan / forced_scan
  → fatigue_candidate
  → approaching
  → offering_form
  → waiting_form
       ├─ timeout / no_guide → farewell → retreat → idle
       └─ guide_requested   → escorting → arrived → farewell → retreat → idle
```

同一时间只允许一个活动交互。第二个疲劳对象只显示在工作台中，不得创建第二个运动任务。

## 3. 模式行为

### 3.1 探索模式

探索模式的唯一任务是构建地图：

- 优先前往可安全到达的未知边界。
- 持续更新雷达地图、轨迹和重定位所需数据。
- 保留避障、卡住恢复、低电量回家和人工急停。
- 禁用疲劳模型推理和评估上传。
- 禁用自动仰头观察、自动跟随、主动问候、手势响应和问卷交互。
- 工作台手动控制仍可使用；手动移动期间继续建图，但不触发任何人员行为。
- 操作员主动点击招手、坐下等姿态动作仍可执行，因为它属于明确的人工指令，不属于自动人员互动。

当探索器连续确认不存在可达未知边界时：

1. 机器狗停止运动并保持探索模式。
2. 工作台显示带 60 秒倒计时的弹窗：
   - “立即进入巡航”
   - “继续保持探索”
3. 60 秒内无操作则自动切换到巡航模式。
4. 操作员选择“继续保持探索”后不再重复弹窗；只有出现新未知区域并再次完成探索，才重新提示。
5. 自动切换前必须再次确认传感器正常、地图可用且未处于手动控制。
6. 如果当时处于手动控制，只更新任务模式为巡航，不夺取操作员的运动控制权。

### 3.2 巡航模式

自主巡航时：

- 按较少访问区域选择巡航目标。
- 疲劳检测持续开启。
- 默认累计巡航 90 秒后，停止导航并进入 20 秒仰头检测。
- 90 秒只计算自主巡航实际运行时间；手动控制、暂停、互动、护送和低电量回家时间不计入。
- 20 秒观察结束且没有有效疲劳候选时，恢复中立姿态并继续巡航。
- 如果观察期间检测到满足阈值的疲劳对象，锁定该对象并进入接近流程。
- 行走期间疲劳检测仍运行；如果取得满足质量要求的有效结果，也可以触发候选，不必强制等到下一次定时观察。

工作台允许调节：

- 巡航间隔：30–300 秒，步长 10 秒，默认 90 秒。
- 仰头检测时长：10–60 秒，步长 5 秒，默认 20 秒。
- 检测时长不得小于疲劳模型完成连续窗口判断所需的最短时间。
- 调节结果在当前运行周期内立即生效，并保存为下一次启动的本机配置。

手动巡航时：

- 疲劳算法持续开启。
- 不自动执行 90/20 秒姿态周期，避免机器狗突然改变操作员正在控制的姿态。
- 操作员可随时点击“立即仰头检测”。
- `fatigue_auto_takeover=false` 时只告警，不自动接近。
- `fatigue_auto_takeover=true` 时允许疲劳候选发起自动接近，但任意手动输入会立即重新接管。

## 4. 周期性和强制疲劳检测

### 4.1 自动仰头检测

一次自动观察执行以下原子流程：

1. 取消当前巡航目标。
2. 输出零速度并确认导航停止。
3. 转向当前最稳定的全身目标；没有目标时保持当前朝向。
4. 调整机身俯仰角，使摄像头抬高。
5. 在规定时间内持续运行多人脸疲劳检测。
6. 没有候选时恢复中立姿态并继续巡航。
7. 发现候选时保持目标身份锁定，恢复适合行走的姿态后接近目标。

### 4.2 工作台“立即仰头检测”

该按钮的语义固定为：

> 立即停止当前自主路径，原地仰头并开始一次检测。

它不是“边走边检测”。手动模式下点击后，机器狗只执行观察姿态，不获得持续自主运动权限；观察完成后恢复手动待命。

### 4.3 疲劳算法开关矩阵

| 状态 | 模型推理 | 显示标注 | 自动触发 |
| --- | --- | --- | --- |
| 探索 + 自主 | 关闭 | 显示“探索模式，检测暂停” | 禁止 |
| 探索 + 手动 | 关闭 | 显示“探索模式，检测暂停” | 禁止 |
| 巡航 + 自主移动 | 开启 | 开启 | 允许 |
| 巡航 + 手动移动 | 开启 | 开启 | 由自动接管开关决定 |
| 巡航 + 仰头检测 | 开启 | 开启 | 由自动接管开关决定 |
| 接近、问候、等待问卷 | 关闭 | 保留最后结果并显示“交互中，检测暂停” | 禁止 |
| 护送 Bedroom | 关闭 | 显示“护送中，检测暂停” | 禁止 |
| 低电量回家或安全保持 | 关闭 | 显示暂停原因 | 禁止 |

“关闭”指停止产生新的疲劳评估和触发事件，而不是只忽略结果。进入关闭状态时清空候选连续计数，防止恢复后使用过期证据。

## 5. 人员接近、问卷和后续行为

### 5.1 自动疲劳候选

候选必须继续沿用现有的多窗口约束：

- 分数、置信度、画面质量和观察时长全部达标。
- 连续多个窗口成立，单帧不能触发。
- 使用匿名目标 ID 锁定同一对象。
- 已有交互、护送、冷却或操作员保持时不得再次触发。

锁定后：

1. 关闭疲劳检测并冻结本次证据摘要。
2. 安全接近目标，保持约 1.2 米距离。
3. 找不到目标或身份不确定时终止，不得切换到另一个人。
4. 到达后仰头、招手并播放语音：
   - “你好，我是守夜犬。你看起来有些疲劳，可以扫描我身上的二维码，或者用手机碰一下 NFC，填写一个简短问卷。如果你需要，我可以带你去休息。”
5. 语音播放完成后创建一个 3 分钟交互会话。

### 5.2 工作台“接近最近的人”

该按钮只在巡航模式可用，语义为：

1. 选择当前摄像头中距离最近且稳定可见的全身目标。
2. 锁定目标并接近到安全距离。
3. 执行与自动疲劳候选相同的招手、语音、问卷等待和后续流程。
4. 该人工指令不要求目标先满足疲劳阈值。
5. 没有稳定目标时明确拒绝，不盲目前进。

### 5.3 固定二维码/NFC与会话绑定

开发阶段：

- 二维码和 NFC 指向 `http://localhost:3000/form`。
- 这只适用于同一台开发电脑上的浏览器测试。

实际部署：

- 表单和对应 API 部署为公网 HTTPS 地址。
- 使用配置项提供完整公开地址，不把 `localhost` 写死到行为代码或页面组件中。
- 当前公网部署不在本阶段实现范围内，但接口设计必须允许直接替换地址。

绑定规则：

1. 同一时间只存在一个 `waiting_form` 会话。
2. 用户打开固定 `/form` 时，页面查询当前活动交互。
3. 语音提示完成后的 3 分钟内，第一份通过校验的问卷自动绑定该交互。
4. 绑定成功后会话立即关闭，后续提交不能再次驱动机器狗。
5. 没有活动交互时，表单仍可作为普通登记使用，但不得触发移动。
6. 多人同时打开时，以第一份成功提交为准；其余页面提交后显示“本次引导已由其他请求处理”。
7. 会话 ID、响应 ID和匿名目标 ID写入事件日志；不保存原始人脸图像。

### 5.4 问卷结果

表单沿用 `UI-design` 分支的两题流程，不再显示昵称或额外同意题：

1. “你现在感觉如何？”：还精神 / 有点累；
2. “要我带你去休息吗？”：好的，带我去 / 不用了，谢谢。

只有以下条件同时成立才进入护送：

- 用户选择“疲劳”；
- 用户选择“需要指引”；
- 问卷属于当前未过期交互。

不满足时都进入友好结束流程：

1. 播放：“谢谢你。也请注意不要让自己太疲劳，记得适时休息。”
2. 招手告别。
3. 在后方代价地图安全时后退约 0.8 米；不安全时原地停止并直接释放交互。
4. 恢复巡航模式，重新开启疲劳检测。

3 分钟内没有有效问卷时执行同一结束流程。

### 5.5 Bedroom 护送

问卷需要指引时：

1. 检查唯一 Bedroom 是否存在并可转换到当前世界坐标。
2. 不存在、地图未对齐或路径不可用时，向用户道歉，通知工作台并结束交互，不能盲目导航。
3. 播放：“好的，请跟着我，我带你去休息。”
4. 以降低后的护送速度导航到 Bedroom。
5. 护送期间关闭疲劳检测，忽略新的候选和问卷。
6. 到达后播放：“已经到休息的地方了，祝你睡个好觉。”
7. 招手告别，安全后退或选择下一个巡航目标。
8. 释放交互控制权，恢复巡航与疲劳检测。

操作员的手动控制、急停和安全保持在护送期间仍拥有最高优先级。

## 6. 工作台设计

工作台与 `/form` 使用同一套 Brutalist 艺术实验视觉系统：纸张底色、
钴蓝与橙色高对比色块、粗黑边框、硬投影、海报式大标题和等宽状态文字。
视觉改造不得改变控制按钮 ID、键盘映射、安全停机逻辑或状态接口。

工作台所有固定文案、动态状态、按钮反馈、输入提示和连接提示均提供中文与
英文版本。页头提供明确的“中文 / EN”按钮，当前选择保存在浏览器本地，并与
`/operator/help` 使用说明页共享；刷新页面或在两页之间跳转不会丢失语言偏好。

`/operator/help` 延续同一视觉系统，集中说明首次使用流程、四种模式组合、
键盘快捷键、状态读法、视频疲劳指标、疲劳交互流程、唯一 Bedroom、扫描周期、
离线预览和安全边界。说明页也提供独立的中英文切换按钮和返回工作台入口。

### 6.1 顶部状态

始终显示：

- 任务模式：探索 / 巡航
- 控制模式：自主 / 手动
- 当前行为及运动所有者
- 疲劳检测：运行 / 暂停及原因
- 疲劳自动接管：开 / 关
- 当前交互阶段和剩余问卷时间
- 电量、导航、地图、摄像头和模型连接状态

### 6.2 模式控制

- “探索模式”和“巡航模式”使用明确的二选一控件。
- “自主 / 手动”使用独立的大按钮，不能与任务模式混成一个开关。
- 切换手动时先停止再确认接管成功。
- 从手动切回自主时，根据任务模式恢复探索或巡航。
- 切换到探索会取消尚未完成的观察、交互或护送，关闭疲劳检测并恢复中立姿态。
- 所有模式变化都写入事件日志。

### 6.3 基础运动按钮

工作台提供按住才运动的按钮：

- 前进、后退
- 左移、右移
- 左转、右转
- 停止

安全约束：

- 仅在手动控制下接受连续速度。
- 按钮松开、指针移出、浏览器失焦、标签页隐藏或网络断开时立即发送零速度。
- 控制报文带递增序号；旧序号不得覆盖新指令。
- 机器人端使用不超过 500 毫秒的“失联即停”看门狗。
- 浏览器不得直接绕过机器人端速度上限和安全复用器。

### 6.4 姿态和交互按钮

保留并补齐：

- 站起
- 趴下并保持
- 坐下
- 招手
- 玩耍鞠躬
- 摇屁股/摇尾巴效果
- 开心动作
- 扒地
- 立即仰头检测
- 接近最近的人
- 停止跟随
- 停止导航
- 紧急停止

当动作因模式、电量、传感器、导航或其他运动所有者被拒绝时，页面必须显示真实拒绝原因。

### 6.5 键盘快捷键

输入框获得焦点时禁用快捷键，防止打字驱动机器人。

| 快捷键 | 行为 |
| --- | --- |
| `W` / `S` | 前进 / 后退 |
| `A` / `D` | 左移 / 右移 |
| `Q` / `E` | 左转 / 右转 |
| `Shift` | 按住时提高到受限快速档 |
| `Ctrl` | 按住时进入慢速精细档 |
| `Space` | 紧急停止并清空当前方向键 |
| `M` | 自主 / 手动切换 |
| `F` | 立即停止并仰头检测 |
| `N` | 接近最近的人并开始交互 |
| `L` | 打开三维雷达地图 |
| `1` | 站起 |
| `2` | 趴下并保持 |
| `3` | 坐下 |
| `4` | 招手 |
| `5` | 玩耍鞠躬 |
| `6` | 摇屁股 |
| `7` | 开心动作 |
| `8` | 扒地 |

页面按钮同时显示快捷键。运动键只在按住期间持续发送，姿态键忽略键盘自动重复。

### 6.6 视频预览

工作台不再只显示原始 `/video_feed/camera`：

- 默认显示策略服务的多人疲劳标注流 `/video_feed/annotated`。
- 框出所有有效人脸，显示匿名 ID、疲劳指数、置信度或质量。
- 保留“原始 / 分析”切换。
- 探索或交互期间暂停检测时，视频上覆盖明确的暂停原因。
- 标注流断开时回退到机器狗原始视频，并显示“模型离线”，不得把旧标注显示为实时结果。
- 工作台同时读取 `/api/score`，显示每个目标的结构化指标；视频框和数值列表使用同一个匿名 ID。

## 7. 三维地图和唯一 Bedroom

### 7.1 页面入口

工作台提供“三维雷达地图”按钮，打开：

```text
http://localhost:3000/lidar
```

当前页面保留地图、实时扫描、机器狗位置、轨迹、视角切换和相机小窗。

### 7.2 Bedroom 规则

- 对外统一名称为 `bedroom`。
- 整个持久地图中只能有一个 Bedroom。
- Bedroom 是操作员明确设置的目的地，不再由帐篷、床等视觉物体自动创建。
- 现有 `sleeping_area` 可在迁移时作为一次性候选，但迁移完成后护送只读取唯一 Bedroom。
- 更新 Bedroom 使用覆盖语义：新位置成功持久化后，旧位置立即失效并从页面移除。
- 更新失败时保留旧 Bedroom，不能先删后写。

### 7.3 标记任意位置

地图进入“设置 Bedroom”模式后：

1. 操作员点击点云中的位置。
2. 页面通过射线拾取获得坐标，并投影到可导航地面；墙面、天花板和没有地面支撑的位置不可确认。
3. 页面显示坐标和预览标记。
4. 操作员二次确认后提交。
5. 机器人端验证地图已对齐、坐标有限、点位处于地图范围且邻近区域可通行。
6. 验证成功后以持久 `MAP` 坐标覆盖唯一 Bedroom。

不要把浏览器相机坐标、Three.js 的 Y-up 坐标或当前会话 odometry 坐标直接写入持久记录。地图流使用世界坐标展示，而持久 Bedroom 必须通过重定位变换保存到 `MAP` 坐标。

### 7.4 标记机器狗当前位置

页面提供“将机器狗当前位置设为 Bedroom”：

1. 使用机器人端最新 odometry。
2. 机器人端执行 `WORLD → MAP` 转换。
3. 通过与任意点标记相同的验证和原子覆盖流程保存。
4. odometry 过期或重定位未锁定时拒绝。

### 7.5 持久数据

建议在世界模型数据库中新增唯一目的地记录，而不是继续复用可存在多行的语义区域：

```text
operator_destinations
  name          TEXT PRIMARY KEY   # 固定为 bedroom
  map_x         REAL
  map_y         REAL
  map_z         REAL
  updated_ts    REAL
  source        TEXT               # map_click / robot_pose / migration
```

更新使用单事务 UPSERT。护送开始时将 `MAP` 坐标转换为当前 `WORLD` 坐标；转换不可用时拒绝护送。

## 8. 接口与数据流

### 8.1 机器人工作台（5555）

保留现有接口并扩展：

```text
GET  /operator/status
POST /operator/action
POST /operator/mode
POST /operator/control-mode
POST /operator/teleop
POST /operator/scan
POST /operator/approach-nearest
```

`/operator/status` 至少增加：

```json
{
  "mission_mode": "exploration",
  "control_mode": "autonomous",
  "fatigue_detection": "disabled",
  "fatigue_pause_reason": "exploration_mode",
  "fatigue_auto_takeover": false,
  "interaction_state": "idle",
  "interaction_remaining_s": null,
  "patrol_interval_s": 90,
  "scan_duration_s": 20,
  "map_completion_prompt": null
}
```

模式和手动速度接口必须直接进入确定性的机器人控制层，不能先交给 LLM 解释。

### 8.2 策略与问卷服务（8000）

增加或扩展：

```text
GET  /api/robot/status
PUT  /api/robot/fatigue-auto-takeover
PUT  /api/robot/scan-settings
GET  /api/interaction/active
POST /api/form/responses
GET  /api/robot/bedroom
PUT  /api/robot/bedroom
```

表单提交增加可空的 `interaction_id`。服务端校验活动状态和过期时间，不能相信浏览器提交的匿名目标 ID。

### 8.3 工作台数据来源

- 5555：实时机器人状态、模式、动作和低延迟手动控制。
- 8000：疲劳结果、交互/问卷状态、标注视频和 Bedroom 管理。
- 8001：只作为疲劳模型服务，由 8000 连接；浏览器不直接驱动模型。
- 工作台跨端口访问 8000 时，CORS 只允许明确的本地工作台来源。
- 8000 不可用时，手动控制和急停仍必须可用；疲劳与问卷区域显示离线。

## 9. 优先级和中断规则

从高到低：

1. 硬件安全、低电量保护、急停
2. 操作员手动速度和停止
3. 操作员明确姿态或任务
4. Bedroom 护送
5. 人员接近与问卷交互
6. 强制或周期仰头检测
7. 自主探索/巡航

任何高优先级行为开始前，都必须：

- 停止较低优先级导航；
- 输出零速度；
- 清理过期目标；
- 恢复不适合行走的仰头姿态；
- 在状态中公布新的运动所有者。

任何终止路径——成功、拒绝、超时、丢失目标、地图失败、模型失败或人工中断——都必须释放行为租约并回到当前任务模式对应的稳定状态。

## 10. 实施顺序

### 阶段 A：状态合同与行为门控

1. 增加任务模式、控制模式、自动接管和交互状态合同。
2. 将探索/巡航从地图阶段中解耦；地图阶段只描述地图事实，不再隐式决定产品模式。
3. 在探索模式彻底门控疲劳推理和自动人员行为。
4. 实现地图完成弹窗状态、60 秒倒计时和无操作自动巡航。

### 阶段 B：工作台手动控制

1. 接入按钮和键盘的按住式速度控制。
2. 增加手动租约、序号校验、500 毫秒看门狗和失焦停止。
3. 完成动作按钮、快捷键、拒绝原因和模式状态显示。
4. 验证手动输入能中断观察、接近和护送。

### 阶段 C：扫描调度和疲劳门控

1. 实现可调的 90/20 秒巡航观察周期。
2. 实现“立即仰头检测”。
3. 将模型开关矩阵落实到策略服务和候选连续计数。
4. 将多人标注视频与结构化疲劳指标集成到工作台。

### 阶段 D：完整问卷交互

1. 增加单活动交互会话和 3 分钟超时。
2. 让固定 `/form` 查询并绑定活动交互。
3. 实现无需操作员确认的首份有效问卷决策。
4. 完成不指引、超时、指引三条语音和动作路径。

### 阶段 E：唯一 Bedroom 和三维地图

1. 增加唯一持久 Bedroom 数据和坐标转换。
2. 三维页面实现地面拾取、预览和二次确认。
3. 增加“机器狗当前位置”标记。
4. 护送改为只解析唯一 Bedroom，并完成旧 `sleeping_area` 一次性迁移。

### 阶段 F：联调与硬件验收

1. 模拟地图、模拟人员和模拟问卷跑完整状态机。
2. DimOS 回放验证租约、恢复和模式切换。
3. 在封闭区域验证真实键盘延迟、仰头画面、接近距离、后退安全和 Bedroom 到达。
4. 最后再制作公网表单部署和实体二维码/NFC。

## 11. 验收场景

### 11.1 模式

- 探索模式运行 10 分钟没有疲劳推理、自动问候或跟随。
- 地图完成后弹窗出现；60 秒无操作自动进入巡航。
- 点击“继续探索”后不自动进入巡航。
- 巡航切回探索能终止尚未完成的交互并关闭疲劳检测。

### 11.2 手动控制

- WASD/QE 按住运动、松开停止。
- 浏览器失焦、断网或页面关闭后 500 毫秒内归零。
- 手动输入可以停止自动巡航、接近和护送。
- 输入框中打字不会驱动机器人。
- 自动接管关闭时，疲劳告警不会抢走手动控制。
- 自动接管开启时可以进入干预，但下一次手动输入立即夺回。

### 11.3 疲劳检测

- 默认巡航 90 秒后停止并仰头 20 秒。
- 调节后的间隔和时长在下一周期生效。
- 探索、交互、护送和安全保持时不产生新评估。
- 多人画面中每张有效人脸都有稳定 ID 和对应疲劳指数。
- 模型离线时原始视频仍可用，且页面不显示旧结果为实时。

### 11.4 问卷

- 提示完成后开始精确的 180 秒倒计时。
- 第一份有效提交绑定当前交互，重复提交不触发第二次动作。
- 180 秒无提交执行提醒、挥手、离开并恢复巡航。
- 不需要指引执行相同的友好结束流程。
- 需要指引时进入 Bedroom 护送。
- 没有活动交互时提交普通表单不会移动机器人。

### 11.5 Bedroom

- 任意地图点和机器狗当前位置都可设为 Bedroom。
- 每次更新后数据库和页面始终只有一个 Bedroom。
- 新位置写入失败时旧位置仍有效。
- 重启并重新定位后，Bedroom 仍位于正确的持久地图位置。
- 地图未对齐、位置不可达或 Bedroom 不存在时拒绝护送。

### 11.6 完整流程

至少连续完成五次：

```text
自主巡航
→ 仰头检测
→ 疲劳候选
→ 接近、招手、语音
→ 扫码/NFC问卷
→ 护送Bedroom
→ 到达语音、挥手
→ 恢复巡航
```

同时至少完成：

- 三次超时返回巡航；
- 三次“不需要指引”返回巡航；
- 每一个运动阶段的一次人工接管；
- 一次模型断线和一次表单服务断线的安全降级。

## 12. 已确定的默认值与假设

- 地图完成提示无操作倒计时：60 秒。
- 自动巡航间隔：90 秒。
- 仰头检测时长：20 秒。
- 问卷等待：180 秒，从提示语音结束后开始。
- 同时活动交互数：1。
- 问卷绑定：3 分钟内第一份有效提交。
- 手动模式疲劳自动接管：默认关闭，可在工作台打开。
- 开发表单：`http://localhost:3000/form`。
- 生产表单：未来配置为公网 HTTPS 地址，本阶段不执行部署。
- 对外休息目的地名称：`bedroom`，全地图唯一。
- 操作员手动接管和急停始终可以中断护送及其他自动行为。
